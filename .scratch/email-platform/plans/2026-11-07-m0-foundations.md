# M0 Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A running `nm` binary in which an instance admin can sign in (password + TOTP, or passkey), create brand workspaces, invite teammates with roles, issue API keys and read an audit log, through a documented REST API and a minimal embedded web UI.

**Architecture:**
- **Crate layout:** one Rust crate, `nm` (lib + bin), with modules organised by domain (`auth`, `users`, `workspaces`, `audit`, `crypto`, `http`).
- **Data:** Postgres through sqlx, with migrations embedded in the binary.
- **HTTP:** axum serves `/api/v1` (OpenAPI generated by utoipa), the health endpoints, and the React UI embedded with rust-embed.
- **Tests:** integration tests use `#[sqlx::test]` (a fresh database per test) and axum-test.

**Tech Stack:**
- **Backend:** Rust 1.96 (edition 2024), tokio, axum, axum-extra (cookies), tower-http, sqlx (postgres, rustls, migrate), utoipa + utoipa-axum + utoipa-swagger-ui (`vendored`), clap, figment, tracing, argon2, aes-gcm, subtle, totp-rs, webauthn-rs, rust-embed, mime_guess, metrics + metrics-exporter-prometheus, chrono + chrono-tz, uuid (v7).
- **Frontend:** React 19, TypeScript, Vite, TanStack Router + Query, Tailwind v4, openapi-fetch + openapi-typescript, @simplewebauthn/browser.
- **Testing:** axum-test, webauthn-authenticator-rs (softpasskey), Playwright, @axe-core/playwright, otpauth.
- **Database for development:** Postgres 16 in Docker.

**Spec:** `.scratch/email-platform/spec.md` (approved 2026-11-07). This plan covers §11 "M0 Foundations". Read §7 "Security", "Licensing" and "UI" before starting.

## Global Constraints

**License**
- Ship a `LICENSE` file containing AGPL-3.0.
- Every source file begins with `SPDX-License-Identifier: AGPL-3.0-only`, written in that file's comment syntax.

**Dependencies**
- **Allowed licenses:** MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, MPL-2.0, Unicode-3.0, GPL-3.0-only, GPL-3.0-or-later, AGPL-3.0-only, AGPL-3.0-or-later.
- **Never allowed:** GPL-2.0-only, SSPL, BUSL, Commons Clause, or any other non-OSI license.
- Another permissive OSI license (for example CDLA-Permissive-2.0 for CA-root data) may be added only with a one-line justification comment in `deny.toml` / `web/scripts/check-licenses.mjs`.
- Postgres 16+ is the only external runtime dependency. No Redis and no message broker.
- No calls to third-party services or CDNs at runtime.

**Passwords and secrets**
- Passwords are hashed with argon2id (m=19456 KiB, t=2, p=1). Accepted length: 12–256 characters.
- Secrets at rest use AES-256-GCM with the master key from `NM_SECRET_KEY` (base64, 32 bytes) or `NM_SECRET_KEY_FILE`.
- Secrets never appear in logs, audit metadata or API responses. The only exceptions are a new API key, new recovery codes, or a pending TOTP secret, each returned once to its owner.

**Sessions**
- The session cookie is `nm_session`: HttpOnly, Secure (except when `NM_PUBLIC_URL` is `http://localhost…` or `http://127.0.0.1…`), SameSite=Lax, Path=/.
- Unsafe methods on cookie-authenticated requests need an `X-CSRF-Token` header.

**API conventions**
- Errors are RFC 9457 `application/problem+json`, with `type` set to `urn:nm:problem:<code>` (codes are listed below).
- Cursor pagination: `?limit=` (default 50, max 200) and `?cursor=`. Responses have the shape `{ "data": [...], "next_cursor": string | null }`.
- Every tenant table has a `workspace_id` column. Asking for another workspace's resource returns **404**. It never returns 403, and it never returns the data.

**Data**
- IDs are UUIDv7, generated in the app.
- Emails are stored trimmed and lowercased.

**Web UI**
- The UI calls only the public `/api/v1` API.
- Initial JS is under 150 KB compressed. Every route component loads lazily.
- The visual design is provisional until the mockups are approved (spec §13.2). Build functional, accessible screens with plain Tailwind and no bespoke design system.

## Review Focus

1. **Email case and whitespace.** An email typed with different case or spaces (`" Ops@Example.COM "`) at login, invite or create-user must resolve to the same account, never a duplicate. Test: Task 7.
2. **Running behind Caddy or another reverse proxy.** Every request then arrives from the proxy's IP, so per-IP lockout would hit everyone. `X-Forwarded-For` is used only when `NM_TRUST_PROXY_HEADERS=true`, and then only its rightmost entry. Tests: Task 6 and Task 8.
3. **A lost authenticator phone.** A recovery code works exactly once, and an operator can run `nm admin disable-mfa`. Test: Task 9.
4. **The last owner** tries to leave, is removed, or is demoted. This returns 409, so a workspace is never left without an owner. Test: Task 10.
5. **An invite link opened while signed in as a different account.** This returns 403, the invite stays unaccepted, and no membership is attached to the wrong user. Test: Task 11.

## Problem codes (`urn:nm:problem:<code>`)

| Status | Codes |
|---|---|
| 401 | `unauthenticated`, `invalid-credentials`, `invalid-code`, `mfa-restart`, `invalid-passkey`, `login-required` |
| 403 | `csrf`, `insufficient-role`, `instance-admin-required`, `invite-email-mismatch`, `user-session-required` |
| 404 | `not-found` |
| 409 | `email-taken`, `slug-taken`, `last-owner`, `already-member`, `totp-already-enabled` |
| 415 / 422 / 429 / 500 | `unsupported-media-type`, `validation`, `rate-limited`, `internal` |

create table api_keys (id uuid primary key, workspace_id uuid not null references workspaces(id) on delete cascade,

**Interfaces:**

create table auth_challenges (id uuid primary key, user_id uuid references users(id) on delete cascade,
